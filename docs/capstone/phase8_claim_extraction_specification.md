## 1. Rationale & Research Contract

Clinical decision support justifications generated by Large Language Models or rule-based reasoning engines frequently interleave multiple distinct assertions into a single paragraph. A monolithic evaluation of a reasoning paragraph obscures whether:
- The patient's clinical diagnosis is accurate while their lab measurement is hallucinated.
- The trial criterion is faithfully quoted while the eligibility conclusion is ungrounded.
- The temporal window is fabricated while the biomarker is supported.

To achieve fine-grained, reproducible grounding evaluation, the **Phase 8 Claim Extraction Contract** decomposes reasoning text into atomic propositions and classifies each into one of six canonical categories without relying on stochastic LLMs.

## 2. Canonical Claim Taxonomy

Every extracted proposition is classified into exactly one of six mutually exclusive [`ClaimType`](file:///c:/Developers/Sneha/Projects/MEDMATCH_V2/scripts/grounding_schema.py#L31-L40) states:

```text
+----------------------------------------------------------------------------------------------------+
|                                      CANONICAL CLAIM TAXONOMY                                      |
+---+----------------------------+-------------------------------------------------------------------+
| 1 | PATIENT_FACT               | Asserts a patient clinical condition, biomarker, symptom, or past |
|   |                            | medical history (e.g. "Patient has stage IV NSCLC").              |
+---+----------------------------+-------------------------------------------------------------------+
| 2 | TRIAL_CRITERION            | Cites or quotes a trial protocol rule, eligibility parameter, or  |
|   |                            | inclusion constraint (e.g. "Trial requires prior platinum chemo").|
+---+----------------------------+-------------------------------------------------------------------+
| 3 | TEMPORAL_FACT              | Asserts a time interval, chronological date, diagnostic duration, |
|   |                            | or treatment milestone (e.g. "Diagnosed within past 6 months").   |
+---+----------------------------+-------------------------------------------------------------------+
| 4 | NUMERICAL_VALUE            | Asserts a lab titer, threshold comparison, age, or clinical score |
|   |                            | (e.g. "ECOG performance status is 1", "Age >= 18").               |
+---+----------------------------+-------------------------------------------------------------------+
| 5 | ELIGIBILITY_CONCLUSION     | Asserts satisfaction, non-satisfaction, or indeterminate status   |
|   |                            | of a criterion (e.g. "Patient satisfies inclusion criterion c1"). |
+---+----------------------------+-------------------------------------------------------------------+
| 6 | INFERRED_CLAIM             | Asserts an extrapolative clinical assumption not directly verified|
|   |                            | in facts (e.g. "Patient likely tolerates checkpoint inhibition").  |
+---+----------------------------+-------------------------------------------------------------------+
```

## 3. Extraction Methodology

The extractor executes deterministically in two discrete phases:

### Phase 1: Proposition Segmentation
Reasoning text is segmented using boundary-aware regular expressions:
- Punctuation delimiters: periods (`.`), semicolons (`;`), linebreaks (`\n`).
- Subordinating and coordinating transitions introducing new propositions (e.g. `", meets"`, `", requires"`, `", trial protocol"`).
- Leading and trailing whitespace and punctuation are stripped while preserving clinical alphanumeric terms (e.g. `EGFR T790M`, `ECOG 1`, `3.5 mg/dL`).

### Phase 2: Prioritized Rule-Based Classification
Each segment is evaluated against prioritized regular expressions:
1. **Inference Detection:** Matches epistemic hedging and speculative operators (`likely`, `suggests`, `assumed`, `presumed`).
2. **Numerical Expression Detection:** Matches explicit numerical comparisons (`<`, `<=`, `>`, `>=`), percentages (`%`), lab units (`mg/dL`, `g/dL`, `cells/uL`), ECOG/KPS scores, and age conditions.
3. **Temporal Expression Detection:** Matches chronological expressions (`within the last X months`, `prior to`, `recently`, `in 2024`).
4. **Trial Protocol Detection:** Matches protocol references (`trial requires`, `inclusion criterion`, `protocol confirms`).
5. **Conclusion Detection:** Matches outcome terms (`satisfies`, `meets requirement`, `fails criterion`, `cannot be determined`).
6. **Factual Fallback:** If none of the specialized patterns trigger, the statement is classified as a `PATIENT_FACT`.

## 4. Input & Output Contract

### 4.1 Extractor Input
- `reasoning_text: str`: Raw reasoning string from `CriterionEvaluationRecord.reasoning`.
- `criterion_id: Optional[str]`: Contextual criterion identifier (e.g., `"c1"`).
- `trial_id: Optional[str]`: Target clinical trial identifier (e.g., `"NCT001"`).

### 4.2 Extractor Output
A list of [`GroundingClaim`](file:///c:/Developers/Sneha/Projects/MEDMATCH_V2/scripts/grounding_schema.py#L90-L115) instances, each initialized with:
- Deterministic `claim_id` (e.g. `"c1-001"`, `"c1-002"`).
- Normalized `claim_text`.
- Resolved `claim_type`.
- Initialized `support_status = UNSUPPORTED` (awaiting evaluation by the Grounding Validator).
- Preserved `source_reference`.

---

## 5. Non-LLM Reproducibility Guarantee

In strict accordance with capstone research requirements, **the claim extractor does NOT rely on an external generative LLM for ground-truth extraction**. All segmentation and classification logic is deterministic pure code, ensuring that repeated runs produce mathematically identical claim breakdowns across experimental conditions.
